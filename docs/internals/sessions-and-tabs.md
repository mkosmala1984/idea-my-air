# Session tabs, watcher and opening

Moved from CLAUDE.md.

- `ClaudeHomeWatcher` watches `sessions/` and every `projects/<dir>/`, debounced 500 ms quiet / 700 ms cap (Air's timings). `ClaudeSessionsService` (application service) refreshes on its events plus every 60 s, holds the session list and live statuses for all projects, and after each change re-targets open tabs by pid (`retarget`) and notifies subscribed tool-window panels.
- `ClaudeSessionVirtualFile` + `ClaudeSessionEditor` (its `SessionPane`, which a plan tab embeds too: `SessionPaneHost`) show a view of a reworked terminal that `SessionTerminals` (an application service) runs apart from the tab (`TransferableTerminalSessionFactory`, internal API, as Air 263's session tabs; the Ghostty VT emulator; `plugin.xml` depends on the content module `intellij.terminal.frontend`) running `claude --resume <id>` (or `--session-id <new uuid>`, in a pinned tab) with `CLAUDE_CODE_NO_FLICKER=1`, `CLAUDE_CONFIG_DIR=<profile dir>` for a session of another profile than `default` (`addedProfileEnv`, `profileEnv`; for `default` the variable is removed from the child, and an IDE that itself runs with `CLAUDE_CONFIG_DIR` makes `default` throw, since the terminal merges its own environment under the added one; `ClaudeSessionVirtualFile.profile`, so `attach`, `claude stop` and the registry lookups use the session's profile too, `claude stop` with the IDE's environment minus an inherited `CLAUDE_CONFIG_DIR` for `default` (`processProfileEnv`) rather than throwing; the tab URL gains `&profile=<name>` only for a non-default one, a restored tab whose profile is no longer listed says `Profile <name> is gone` and starts nothing) and `CLAUDE_CODE_IDE_SKIP_AUTO_INSTALL=true`, and on every start, `--resume` included (claude rebuilds a recorded system prompt from the current flags after a compaction), `--append-system-prompt` with `appendedSystemPrompt` (`SessionSystemPrompt.kt`): the branch's base is `branch.<branch>.myAirBase`, read from git rather than named, so every session shares one prompt; the My Air MCP tools and what each is for (`SessionSystemPromptTest` checks it names every tool of `FoldersMcpToolset`); the plan rules (read the plan with `my_air_plan_get` at the start, keep the task's status and next step current, delete or move only with the user's agreement); and with briefs on, call `my_air_set_brief`, naming the plan task in `plan_task`; with Agents file and title their sessions on too (`MyAirSettings.fileSessions`, effective only with briefs), give it `title` and `folder` without asking, reading `my_air_folders_get` first. With briefs on it also gets `--settings ~/.my-air/hooks/brief-reminder.json` (`BriefReminder.kt`): a `UserPromptSubmit` hook, PowerShell passed as `-EncodedCommand`, that adds a reminder to every prompt until the transcript holds a `my_air_set_brief` `tool_use` (the prompt alone got it called in about a quarter of sessions). A session in a plan (`sessionPlan`: the task its brief names, else the plan row a new session was started from, `PlanStart`, else the plan folder it shows in) also gets `--append-system-prompt-file` with `planPrompt`: the plan's name, path and description, its task's and milestone's, Markdown kept whole, no statuses; the file (`~/.my-air/prompts/<IDE pid>-<uuid>.md`, `PromptFiles`) lives until the process ends, since claude reads it again after a compaction, and files of IDEs gone are deleted when the next is written. claude keeps a session's recorded prompt on `--resume` until a compaction, so a session resumed into a plan gets the context only then. A session a background job runs (the registry read afresh at start, as a restored tab may start before the first refresh) gets `claude attach <jobId>` instead, with the same variables and nothing else, since claude refuses or forks a `--resume` of it; the tab keeps the job (`ClaudeSessionVirtualFile.job`) and follows the job's entry rather than its pid, as a tab parked by `/bg` follows the job it parked into (`shownBy`, used by `retarget` and the statuses `SessionTerminals` reads). `SessionTerminals` learns the process pid from `TransferableTerminalSession.processId` (`claude` itself, not a shell); text typed for it goes through the view's `sendText`. One process per tab file: a tab binds a view of it (`attach`, `bind`), a second tab of the same file (a split) takes it and the first shows Show Here. Closing the tab (`release`) ends the process unless Keep sessions running after their tab closes is on (`MyAirSettings.keepDetached`, default) or the platform closes it to reopen it (`CLOSING_TO_REOPEN`); then it runs on detached, and every refresh ends a detached one that `retires` (`Retirement.kt`, as Air's `DetachedTerminalRetirement`: detached at least 60 s, `idle`, no background task started by this process still open; needing input keeps it); closing a working session's tab says so once per run. A process showing a job (`jobOf`: attached, or parked into one) is only a view of it: closing its tab ends it unless the tab reopens, whatever the setting, and the job runs on. A detached session counts as a tab wherever one does (`SessionHosts.findTab`/`openTabs`, `retargetOpenTabs`, the heads), so opening it from anywhere reopens the same file and binds the same process. Close and Settle, a process ending by itself and closing its project (`SessionTerminals.ProjectClose`) end it. Closing a project, exiting or restarting the IDE first asks when a process it would end `interrupts` (`CloseConfirmation.kt`, as Air's `AgentThreadViewProjectCloseHandler`: the registry says working or needing input, or a background task it started runs; idle, starting and ended ones never, nor a view of a job): `ProjectCloseConfirmation` (`projectCloseHandler`) about the processes that last showed in that project, tab or detached, and not during an exit; `ExitConfirmation`, an `ApplicationListener` that `SessionTerminals` registers when it is created, about all of them. The texts come from `confirmation`; the statuses from the last refresh. The tab's icon is the session's status, with a branch badge in its corner when the session works in another work tree than its home (`TabMark`, `tabMark`: the window's work tree for a session of the window's project, its project's otherwise; compared by root, from `workDir`, so `EnterWorktree` counts; the heads are read from HEAD files on the refresh thread, `Git.head`, kept in the service state so a checkout alone re-marks, and the mark stored on the tab by `retargetOpenTabs`, so the providers do no IO); a session of another project than the window's gets that project's icon after it and its colour, a session of the window's project in another work tree that tree's colour, either mixed into the tab background (`ClaudeSessionTabColorProvider`, `projectColor`: the internal `ProjectIconPalette`, as the initials icon picks it, which asserts the EDT while tab colours are asked for off it, so it is read there once per path and the tab repainted); the tooltip names the project, and for a worktree its root and branch (`tabTooltip`). Close and Settle (`CloseAndSettleAction`, in `CloseEditorsGroup` after Close, so in the tab's menu) settles the tab's session, then closes it; when the tab shows a job the registry still lists it also runs `claude stop <jobId>` off the EDT (5 s, as Air's Mark Done; a timeout or a non-zero exit is logged as an error with its stderr). Tabs survive a restart: the file's URL is `myair-session://<id>?cwd=…&project=…` in `ClaudeSessionFileSystem` (`SessionTabUrl.kt`), computed from the session it shows now, so the platform saves it with the open tabs (order, splits, pins) and resolves it on startup, always as a new tab and never into Recent Files (`OptionallyIncluded`); a restored tab gets `--resume`, or `--session-id` when the session has no transcript yet, and starts when first selected, but not while its directory is gone or the registry shows its session running other than as a job, where it says so and offers Switch to Window / Open Anyway. Above the terminal a header (`SessionHeader`, `headerText`) names the session the tab shows now: title, project in its colour, branch of `workDir`, the brief's count, and under them its goal (else its task in progress); it follows `ClaudeSessionsService`, so `/clear` and a new brief change it. On its right New Session Here (`NewSessionHereAction`, `newSessionHere`, with `NEW_SESSION_HERE_ICON`, a small asterisk with a green plus) starts a new session of its project in the folder the session works in (`workDir`; the tab file's `cwd` before a scan has seen it), filed in the folder the session shows in (`placeOf`; a plan task's session: its plan folder), disabled once that folder is gone. `CenteredTerminal` gives the terminal the number of columns set as Session tab width (`MyAirSettings.terminalColumns`, 0: the whole tab) and centers it, counting columns as the terminal's editor does (visible width over `CharacterGrid.charWidth`, rounded down; `EditorGrid` reads the visible one of the output and alternate-buffer editors); `CenteredTerminalTest` lays out a scroll pane in a border standing for that editor.
- `ClaudeSessionOpener.open` goes, in order: a tab in this IDE (`SessionHosts.findTab`, which includes Air's tabs read through reflection on `getThreadId`/`getSessionId`) → a tab in another IDE running this plugin (`TabsSync.focusElsewhere`: `AllowSetForegroundWindow` for that IDE, then a request file) → a warning when the registry shows the session running in another program other than as a background job (which a new tab attaches to), offering its window (`SessionHosts.hostWindow`, the nearest ancestor of the `claude` process that owns a visible window) → a new tab. An agent starts a new session with the MCP tool `my_air_session_start` (`FoldersMcpToolset`): a configuration by name and/or model, effort, directory, added directories, a worktree off a base it must name, maybe on a new branch (`createWorktree`, the popup-free core of `startInWorktree`), a plan task (`PlanStart`), and a folder, which files the session and, without a directory, gives it as the tree's menu does; the first message is the configuration's prompt followed by the agent's, either alone, never neither (`firstMessage`); the tab opens in the IDE project the call came through, and every input or `git` failure (`GitFailure`) goes back to the agent instead of a dialog (`sessionStartPreset`, `SessionStart.kt`).
- `TabsSync` republishes this IDE's tabs on tab open/close (project listener), project startup and re-targeting; it withdraws its file on dispose.
