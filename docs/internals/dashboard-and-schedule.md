# Sessions dashboard and scheduled tasks

Moved from CLAUDE.md.

- Sessions dashboard (`dashboard/`): Tools › Open Sessions Dashboard and a Claude Sessions toolbar button open one editor tab per IDE (`DashboardVirtualFile` under `myair-dashboard://sessions`, `DashboardFiles`; the action brings forward the window already showing it, `tabs/SingleTab.kt`'s `SingleTabListener` closes a second one restored in another window). `dashboardOf` (pure) puts every session not settled in Now (needs input, working, unread), Unfinished or Finished: a session has open signals for a brief task not completed, a file it wrote uncommitted in the work tree it lies in, commits its branch's upstream (else base) lacks, an open plan task (in progress, waiting, blocked), or its agent's last text ending with `?` no human prompt answered (`ClaudeSession.asks`); a merge of its branch (`ClaudeSession.lastBranch`, the `gitBranch` of its latest message) into its base (`Git.branchFate`: a first-parent merge whose second parent holds the tip, `(pull request #<n>)` its number) cancels all but the uncommitted files. Unfinished groups by area (`areaOf`: the plan folder, else the folder at depth two, else the project's name); a session whose git failed stays there, one whose git is still being read waits in the folded Checking git group (`Dashboard.checking`), since a merge may yet end it. `GitFacts` reads off the EDT each work tree's uncommitted files (`Git.uncommitted`) and each branch's fate (`branchFate`) on its own, newest session first, handing the sessions each read completes to the editor as it goes (a first read of every one took 3 minutes on 964 sessions; the last 2 days' land in seconds), rereading a work tree only when its HEAD, index, packed-refs or FETCH_HEAD changed or a session it serves got a newer message or other changed files, and a branch only when those or its ref changed; a removed worktree's branch is read in the project's checkout. What it read is kept in `~/.my-air/dashboard-git.json` (read at the first read, written after one that ran git, a `format` other than its own read again from git), so after a restart only what changed is read (0.8 s instead of minutes on 964 sessions). Analyze in its header (beside a chooser of 7, 14, 30 days or all by the last message, application property `dev.myair.dashboard.analysisDays`, default 14) has Haiku tell what is left in each session of Unfinished and Finished not known merged (git still being read does not hold it back) and with no current analysis (`analysisCandidates`): `AnalysisRun` runs 3 at a time `claude -p --model haiku --no-session-persistence --output-format json --json-schema` with `--tools ""`, `--strict-mcp-config` and `--setting-sources project` in `~/.my-air/analysis/` (the user's `CLAUDE.md` still loads), killed with its descendants after 2 minutes or on Cancel, on a digest (`digestOf`: title, brief, plan task, chips, files written, every human prompt and the last 5 agent texts read from `ClaudeSession.transcript`, the file the session was read from, cut to 40000 characters by dropping the oldest prompts); the reply's `structured_output` (`verdict` done/open/unclear, `left`) is stored as `~/.my-air/analysis/<id>.json` (`AnalysisStore`, read by every IDE), counts only while the session's last message is the one stored with it, and shows as a chip and, unless done, a `Left:` line under the row, wrapped to the tab's width (the content panel tracks the viewport's width); it never moves a session between sections. A failed analysis shows `analysis failed` until the next run tries it again.
- Scheduled tasks (`schedule/`, as Claude routines but run by the IDE): `~/.my-air/scheduled-tasks.json` (`ScheduledTaskStore`, version 1, shared by every IDE; unknown keys and a repeated id throw, and a broken file runs nothing and shows its error in the tab) holds `ScheduledTask`s: a `Preset` (name, model, effort, directory, added directories, the prompt, required; no worktree, button or askMore) plus weekdays and one local time (`Schedule`), enabled, `--allowedTools` and a folder its runs are filed in; `since` (set on creation, a changed schedule or a re-enable, `edited`) keeps slots from before an edit from running. `ScheduledRuns` (application service, started by `ClaudeSessionsService`) ticks every 30 s once the service has `loaded` (before, no session or folder is known) and only while a project is open: a task runs its latest slot (`dueSlot`) when it is at most 12 hours old (`CATCH_UP`), so a slot missed while no IDE ran catches up once at the next start but not an hour before the next one. The run record `~/.my-air/scheduled-runs/<task id>/<yyyy-MM-dd'T'HH-mm>.json` (`RunRecords`; a Run now: `...-ss-manual.json`) is created by a rename that never replaces (`claim`), so of several IDEs the one whose create wins runs the slot; records are pruned after 90 days. A run that the task's previous run, working or needing input, would overlap is recorded `SKIPPED`; otherwise the run, checked first (`preStartError`: an open project, its directories, its folder, `claude` on PATH), is marked seen as of its start (so `firstSight` cannot swallow its reply), filed, and started with `SessionTerminals.startDetached`: an interactive `claude --session-id` with no tab (`deferSessionStartUntilUiShown = false`, 80x24 until a view binds), detached from the start, so it shows in the pinned list with its live status, a permission or AskUserQuestion prompt makes it need input, its reply makes it unread, and a click binds it in a tab. Its process does not retire while its session is unread (`ScheduledRuns.held`, `retires(held)`), so the result stays in the pinned list and on the taskbar until seen. The run is marked seen through `ClaudeSessionsService.seenStore`. Each tick settles the runs still `STARTING`/`STARTED` (`verdict`, pure): one whose session wrote its first message `RAN`; this IDE's one left starting (an exception cut the start), whose process ended first, or that has no first message 5 minutes after its start (closed) fails, as does one whose IDE is gone (`ideAlive`: pid and start instant, `ideStart` in the record, as pids are reused). A run before its first message is held from retiring too, so the deadline, not the idle rule, ends one stuck on a start-up question. Every `FAILED` record (with its reason) is notified once, by the IDE that wrote it, in the sticky group `My Air Scheduled Tasks` with Open Scheduled Tasks, as is, once per error, a broken task file (nothing runs) or run record (left out of every read, `RunRecords.broken`). The registry tab (Tools › Scheduled Tasks and a Claude Sessions toolbar button; `ScheduledTasksVirtualFile` under `myair-scheduled://tasks`, one per IDE as the dashboard's) lists each task with its schedule (`scheduleText`), next slot, latest run (`taskRow`, red when the newest not skipped failed), Run now, Edit (`ScheduledTaskDialog`), Enable/Disable, Delete, and its runs with their sessions (a group kept open across rebuilds once opened); it rereads on every service change and every 30 s.
