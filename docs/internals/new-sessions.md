# New sessions: worktrees, configurations, composer

Moved from CLAUDE.md.

- `NewClaudeSessionInWorktreeAction` (toolbar and Tools menu, next to the plain new-session action) lists branches in a popup: the default branch (`origin/HEAD`; without `origin` the one local `main`/`master`), the 5 recent bases (application `PropertiesComponent`, keyed by the repository's main checkout), the rest. The pick's local branch (a remote pick: its local namesake, created tracking it when missing) is checked out in `<worktrees dir>/<name>` without a new branch (`Git.addWorktree`); a linked worktree holding it is removed first (`git worktree remove`) when it is clean (no modified or untracked file), unlocked and no running session works in it. When it cannot be, or the main checkout holds it, the pick becomes the base of a new branch `worktree-<name>` (`git worktree add --no-track`, `addBranchWorktree`), the pick stored as the branch's base in the repository's config (`branch.<branch>.myAirBase`, `Git.setBase`, so `git branch -m` carries it), `<name>` being `worktreeName`: the pick without non-alphanumerics, today's date and the first 4 characters of the new session id (`main-2026-10-28-3fb8`); gitignored files matching `.worktreeinclude` are copied in, as `claude --worktree` does (`claude` itself takes no base branch), and every server of a `.mcp.json` in or above the worktree that its `.claude/settings.local.json` has not decided on goes into that file's `disabledMcpjsonServers` (`declineProjectMcpServers`), so `claude` does not ask about it at the first start. After the base, the action (and the tree menu's) offers Check out <base> or New branch off <base>... (`branchPopup`): a popup in the composer's look (`showNewBranchPopup`, `NewBranchPanel.kt`; the card, bar, chips and send button are shared in `Composer.kt`) takes a flat name typed or suggested from a task or a Jira key, the task then going to the session as its first message (`suggestBranchName`, `BranchNames.kt`: `claude -p --model haiku --no-session-persistence`, so it leaves no transcript, with `--allowedTools` the Jira tools set in Settings (`MyAirSettings.jiraTools`); Haiku answers with a slug alone and the first Jira key of the task (`ticketKey`) goes before it, `TR-1234-short-description`); `addBranchWorktree` makes it off the base in `<worktrees dir>/<branch>` (`dirName`), the base stored. The worktrees dir is an application setting (`MyAirSettings`, the one class left in `dev.myair`, Settings › Tools › My Air), default `.claude/worktrees`, relative to the main checkout. `Git` (`Git.kt`) runs the `git` on PATH and throws with its stderr; the pure parts (`baseChoices`, `pushRecent`, `defaultBranch`, `worktreePath`) are in `Worktrees.kt`, and `GitTest` runs real `git` in a temp dir. The tree's menu on a project row, or on a folder that has or lies in one with a working directory or a bound one, offers both new-session actions in that directory (`nodeDir`, `NewSessionInDirAction`): the nearest such folder decides, its `workdir` before its first bound directory (`startFolder`, `Folder.startDir`), and one gone disables them rather than handing over to a folder above; a session started from a folder row is filed in that folder (`startNew`'s `folderId`). Open in IDEA and Open in Terminal (`OpenInDir.kt`) sit beside them, on session rows too (`openDir`: the session's cwd) and as IDEA and Terminal links at the end of the project row in the context pane's Environment section: IDEA focuses the open project of this IDE or opens it here, Terminal adds a tab at the directory to this project's Terminal tool window.
- Session configurations (`Preset`, `store/Presets.kt`) live in `~/.my-air/presets.json`, shared by every IDE and edited in Settings › Tools › My Air, where a Claude Profiles group (`ProfilesEditor`, `actions/ProfileSettings.kt`) adds a profile (name, directory defaulting to `~/.my-air/claude-profiles/<name>`, created with `projects/` and `sessions/`, see the next item for what it can copy from the default profile, then a session tab of it opens for Claude Code's first-run login, and the `claude mcp add` command for the IDE's `idea` http server is shown, `mcpAddCommand`; `ProfileChecks.kt`) and removes one from the list, keeping its directory and refusing while a session, tab, preset, plan or review manager or reviewer uses it (`removeRefusal`) (`PresetsEditor`, `PresetDialog`; the fixed base is picked from the branches read off the EDT from the project field's repository, or the IDE project's when it is empty): name, `--model`, `--effort`, a project directory (none: the IDE project's), no worktree / a worktree off a fixed base / off a base picked in the popup (`startInWorktree`), `--add-dir` directories, whether it gets its own toolbar button (an initials icon: `AvatarIcon` from the name, its colour a hash of it), an optional `profile` (a name; unlisted fails the start, a scheduled task takes it too), a first message (`prompt`, which the button sends) and whether the button opens the composer with that message typed in to add to it (`askMore`, `showPromptPopup(project, preset)`). In place of a model and effort it may list model and effort pairs (`variants`, `Variant`: none or at least two, typed one per line in the dialog, `parseVariants`; the key is left out of the file without them): its button then lists them in a popup under itself (in the dropdown, a submenu), and the pick starts it as a preset with that pair (`withVariant`); where nothing is picked (the composer's configuration chip, `my_air_session_start`) the first pair counts (`firstVariant`), and a scheduled task takes none. `PresetsGroup` on the panel toolbar shows those buttons and a dropdown of all presets; it reads the file on every toolbar update, cached by modification time, and names a broken file in the dropdown. Model and effort apply only to new sessions: `--resume` gets none of a preset's flags. New Session Here, Continue Session (its prompt names the real transcript path, `ClaudeSession.transcript`) and `my_air_session_start` (`profile`; `my_air_sessions_find` gives it for a non-default session) keep or take the session's profile. A session's menu (tree and list) offers New Session with Same Settings and Save Settings as Configuration...; both take `presetOf(session)`: its model, effort, profile, project, added directories, and a worktree with the base picked at start when its cwd is not its project.
- Copy from the default profile (`store/ProfileCopy.kt`, `NewProfileDialog`): the New Claude Profile dialog can copy, once (later changes are not synced), items from `~/.claude` into the new directory, one checkbox per `CopyItem` under four headings: Look (`statusLine`; `theme`, with `themes/<name>.json` for a `custom:<name>` theme) and Behaviour (`model`, `effortLevel`, `language`), ticked by default and written as a new `settings.json` holding only those keys in source order (no HTML escaping, so commands stay as they are); Instructions (`CLAUDE.md`) and Skills, agents and commands (the `skills/`, `agents/`, `commands/` trees), unticked. Not copied: `.credentials.json` (a second copy of the refresh token could log the default profile out; the user signs in in the tab that opens, with the same account, which the dialog advises), `env` (it can hold secrets), `hooks` and `permissions` (code and trust from the default profile), `modelSettings` and `attribution` (not yet looked at), plugins (until it is tested whether `claude` installs enabled plugins missing on first start), `.claude.json` and all state. A missing source shows the item disabled with its reason; a broken one (invalid or non-object `settings.json`: the five key items; a `custom:` theme without its file or with a name holding a separator or `..`: the theme) in red. With anything ticked the directory must be absent or empty, and it may not lie in `~/.claude`. Add runs in a modal, non-cancellable task: copy, then `projects/` and `sessions/`, then `profiles.json`; any failure deletes everything under the directory (the directory too when it was absent), shows the failing step and registers nothing; paths that could not be deleted are named. A crash mid-copy leaves a non-empty directory the next attempt refuses; it is removed by hand. Links, junctions and other special entries in the copied trees fail the copy, naming the path: the JDK (JBR 25) reports a junction read without following links as both `isDirectory` and `isOther` (not `isSymbolicLink`), so the copy tests `isOther` before `isDirectory`; `ProfileCopyTest` checks this with a real `mklink /J`. `statusLine` commands are copied as they are, so the scripts they run stay in the default profile (the dialog says so). One `idea.log` line names the profile and the copied items.
- `PromptPanel` (`prompt/`), styled after Air's composer: a card with the first message, chips for the configuration (Default, then `presets.json`), model (default `opus`) and effort (default `medium`), the profile (Default, then `profiles.json`: `Choice.profile`, kept with the other choices and a draft; an unlisted one fails the start with its name) and a send button; under it a bar of project › workspace › branch, read as a phrase (workspace: Checkout, New worktree of the base, New branch off it in a new worktree, named on a line of the bar of its own, shown only then, or by its Suggest from the message, as that popup does, or Existing worktree, which puts in place of the branch a chip of the project's linked worktrees whose folders exist, newest first with the branch checked out in each, `gitWorktrees`, and starts in the one picked: `Choice.existing`, `toPreset(base, existingDir)`); the project chip lists (the configuration's own project, the open projects, then the IDE's recent ones that exist, each once as a path, read off the EDT, `projectChoices`; a stored project gone is forgotten, `present`; a start whose directories are gone is refused in the panel before the message is cleared; `Choice.project` replaces the configuration's directory, and choosing a configuration resets it) and the branch chip shows the checked-out one or, for a worktree, the base picked in a searchable list (`baseChoices` of the configuration's directory's repository, read off the EDT, tagged current/default/recent by `branchTag`); the panel is 720 px wide and its minimum size is its preferred one (the empty editor area's `GridBagLayout` lays out at minimum sizes once narrower), and a popup holding it is fitted to its height again whenever a row shows or hides (`relayout`), as a popup keeps the size it opened with. A configuration sets the rest, each may then be changed, and the next panel opens on the last start's choices (`restore`, `PromptChoices.kt`; the base through the recent bases), or on a message typed and not sent with the choices and base it was typed with (`Draft`, `opening`; application properties `dev.myair.prompt.draft.*`, written on every change while there is a message, removed when it is sent or emptied). Ctrl+V of an image saves it as a PNG in `~/.my-air/images/` (images older than 30 days are deleted, off the EDT, whenever a panel opens: `pruneImages`) and of copied files keeps them where they are; either goes into the message as an `@path` mention, quoted when it has a space (`pastedMentions`, `PastedImages.kt`), which `claude` attaches at once, while a bare path it reads only with a tool call. The paste is an action on the text area, since the IDE's own paste takes only text. It starts the session through `startPreset`. The chip Plan after effort (a toggle, kept with the other choices and a draft, and across a change of configuration) shows a Plan name line in the bar; a start with it on, its name required, starts the session as the manager of a new plan of that name (`startAsPlan`, `planview/NewPlan.kt`) in the folder bound to the project directory, or beside the plan that folder is or lies in, else at the top level (`planParentFor`), the worktree made first, and opens the plan tab instead of a session tab; the manager's first process gets the panel's flags and message through `PlanFiles.adopt`'s first arguments. Opened from a configuration (`PromptPanel(project, started, from)`), it starts on that configuration with its prompt and a space typed in (`openingMessage`) and stores no draft until the message changes; choosing another configuration replaces the message while it is empty or the previous one's prompt untouched (`switchedMessage`). The prompt goes last, after `--` (`Preset.claudeArgs(prompt)`): `--add-dir` is variadic and a lone word like `mcp` would be a subcommand. It fills the empty editor area (`PromptEmptyState`, platform EP `editorEmptyStateComponentProvider`, internal API in `fileEditor.impl`); every available `RICH` provider is stacked there, so Air's composer shows too unless its registry key `air.inline.empty.state.prompt` is off. `NewSessionWithPromptAction` (first on the main toolbar and the Claude Sessions toolbar, and in the Tools menu) shows the same panel in a popup.
