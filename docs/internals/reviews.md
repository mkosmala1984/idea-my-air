# Review folders

Moved from CLAUDE.md.

- Review folder (`review/`, `reviewview/`, `store/Reviews.kt`, `store/ReviewProfiles.kt`): a folder holding the review of one branch (`BranchReview`: branch, base, work tree `dir`, PR number, the linked `plan` folder id, the `manager`, summary, `chapters`, `runs`, `findings` with a `Report` per run, `questions`, `next` counters per id prefix, the mirror's `blockers`) in `~/.my-air/reviews/<folderId>/review.json` (`ReviewFiles`, format 1, written atomically; the folder's id is the only link, so a folder gone leaves an ignored file); a review folder holds no plan and lies in no review or plan folder, which every structure write checks (`refuseKindPlacement` in `ClaudeSessionsService.updateFolders`, `folders/KindPlacement.kt`, over the ids of every `review.json` and `canvas.json` on disk, only placements new in the write counting; a review folder also lies in no canvas folder, see canvases.md), the drop, New Plan..., Make Folder a Plan and Turn into Plan disabled where it would refuse (`inReviewOrCanvas`); a review's manager cannot become a plan's (`managerRefusal`, Turn into Plan). Reviewer profiles (`ReviewProfile`: reviewers with name, first message, `model`, `effort`, and optionally a Claude Code `profile`, a name that must be listed in `profiles.json`, else the run's start fails naming it; its `claude --bg` gets that profile's `CLAUDE_CONFIG_DIR` through `Reviewers.start`, and `learnSessions` finds the session by job id in the merged registry) live in `~/.my-air/review-profiles.json` (`ReviewProfileStore`, read again when the file's time or size changes; a missing file means none, a broken one is a failure the panel shows). `ReviewService` (application service, state on the EDT) reads every review off the EDT on each `ClaudeSessionsService` change and on file events under `reviews/` (`reviews`: by folder id, only folders in the structure, a file that cannot be read a failed `Result`; `facts`: `ReviewGit` per review an open review tab watches (`watchGit`), read with `Git` only when its `GitStamp` changed (HEAD file, the time of the ref it names and of `packed-refs`, the index, the repository's `config`, `review.json`, the files its findings name): the work tree state against the review's `base`, an error when another branch than the review's is checked out, HEAD, commits since the reviewed one, `Git.changedLines` since each finding's commit for `maybeFixed` (none for a commit a rebase took out of HEAD's history); `my_air_review_get` and `my_air_review_apply` read git on each call, off the EDT; the tree and the mirror read none) and is the only writer (`update`, `create`, `moveManagers` on `/clear` and `/resume`, after the folders' `carryOver` and without the mirror), so the tab and the MCP tools see one state. It learns each run's session from the registry by job id (`learnSessions`: a run started as a `claude --bg` job, which ignores `--session-id`, gets the session of the live entry with that `jobId`, and that session is filed in the review folder, so manager, reviewer and fix sessions show as children of its row in the tree; `runStatus`, from the live entry of its job (`liveJobs`: job to status): reported once it reported, whatever its job does (a reviewer stays attachable for questions, never stopped), else running while it works or is not yet seen, waiting ("needs input") while it needs input, stopped ("stopped without report") while idle, failed when it had a session and no live job; only running keeps the mirrored plan review in progress) and mirrors the review into its linked plan (`mirrorToPlan`, `mirrorDue`: the plan's review status and commit follow the runs, each standing blocker finding becomes a plan blocker `B<n>` with a one-line text mapped in `blockers`, a blocker no longer standing is resolved; computed in the folders write against the structure read from disk there, the review written there before the structure, and a mirror that does not converge throws). Three MCP tools in `ReviewMcpToolset` (`my-air-mcp.xml`), each naming the review folder by its id or else its path (`withReview`), the reviewer's and the manager's prompts naming it by id, which a rename keeps; `my_air_review_get` gives the folder and the linked plan as paths, and `merge_base`, `range` (of a Whole branch run), its `commits` and `files` (`Git.rangeSize`) and `stored_base` (`reviewJson`): `my_air_review_get(folder)`, `my_air_review_apply(folder, changes)` (`ReviewChanges`: ops on summary, chapters, finding states, PR, base, questions and runs; a new base (`set_base`) is first checked off the EDT with `baseProblem`, the reason `readGit` would give (among them `Base <ref> already contains <branch>: nothing to review` when its merge base with HEAD is HEAD, a review-only rule), and refused with it, else also stored as `branch.<branch>.myAirBase` (`storeBase`, then `ActiveSession.baseStored` so Session Context and Branch Diff read it again); an unknown op or field fails naming it; Fix with Claude on a finding accepts it only when open, `acceptIfOpen`) and `my_air_review_report(folder, run, commit, findings, questions)`, which a reviewer calls once with the run id its prompt names and the commit at the end of the run's range, any other refused naming it (`mergeFindings` merges its findings into the review's, each joining the nearest finding of the same file and category at most 3 lines away that no other finding of the same report joined; a re-report replaces that run's questions). The tab is `myair-review://<folderId>` (`ReviewVirtualFile` under `ReviewFileSystem`, `ReviewTabs`, `ReviewOpener`; Open Review in the tree's menu on a review folder) with `ReviewPanel` on the left and the manager's terminal on the right, on the plan tab's `FolderTabs` and `ManagerTabEditor`: the manager is a session stored in `review.json` (`reviewManagerStart`: new in the review's work tree with the main checkout as its project, else resumed) given `reviewManagerPrompt` and, while its session has no transcript, `REVIEW_MANAGER_FIRST_MESSAGE` after `--` (read the review and the diff, fill the summary and chapters, report in a few lines), the prompt telling it to fill the summary and chapters, start no reviewer, and publish to the PR or change a finding's state only on the user's word, and that the folder's base wins over `myAirBase` and `my_air_review_get` gives the current range (no counts: the prompt is recorded once per session). The panel (`reviewViewOf`, `ReviewView.kt`) shows the cards Header (branch, base with Change Base..., a popup of `Git.nearestBases` without the refs holding every commit of HEAD, the pick going through `storeBase` as `set_base` does; when `myAirBase` of the branch differs, a line naming it with Use it, which does the same; PR link, reviewed commit, commits since), Summary, Explanation (chapters with their files and changes), Reviewers (a profile's reviewers and their runs, with precision from triaged findings), Findings (filter all/open/blockers, grouped under folding severity heads; each finding drawn as a plan task: folded to one head line, its state as a button that changes it, id, summary, file name and line, maybe-fixed mark, agreement across runs and a `...` menu; a click unfolds it into a white card with its path linking to the base diff, category, failure scenario, decision and every report, and the reason or fix commit field while that edit is open) and Questions; texts are edited in place (`ReviewEdit`). Run starts each reviewer of a profile as `claude --bg` in the work tree (`Reviewers.start` through `runClaude`, whose output goes to temp files read after it exits, as the daemon it leaves may inherit its handles, and whose 30 s timeout kills only a `claude` still running; `reviewerArgs`: `--append-system-prompt` with `reviewerPrompt`, naming base, merge base, head, the range with its commit and file counts read off the EDT at the start, and to report one question and stop on an empty diff, the profile's first message after `--`; `parseJobId` reads the job id from `backgrounded · <id>`, anything else throws) over a range from the merge base or, for new commits only, from the last reported commit (`rangeFor`, which throws on an empty range; the Run actions are disabled with `runProblem`'s reason); the run is stored with that job id and reports by run id. New Review... (asks for the manager's profile when others are listed, `default` preselected, and stores the manager in `review.json` at creation, `PlanManager.profile`; tree menu, `NewReviewAction`, `reviewStart`, `startReview`) makes the review of a branch: its work tree (`reviewWorkTree`), `review.json`, then the folder `Review: <branch>` (`reviewParent`: beside the plan of the place when it lies in one, never inside a review or canvas folder, beside the outermost of them), and opens the tab. A review folder's row and its tab have the review icon (`REVIEW_ICON`) and the row, on its right before the session count, its standing blockers in the needs-input colour (`reviewBlockers`, `blockerCount`: blocker findings open or accepted), repainted on every `ReviewService` change.
