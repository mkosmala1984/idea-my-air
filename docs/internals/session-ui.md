# Session lists, Session Context, Branch Diff

Moved from CLAUDE.md.

- A tree row of a session is one status icon (`sessionIcon`, `SessionIcons.kt`, the same on its tab: a thin grey asterisk without a process, the orange asterisk as a spinner while working (`WORKING_ICON`, eight fading half-rays painted in code, one turn a frame), an amber disc with `!` when it needs input, a blue asterisk when unread, else the orange asterisk; the SVGs have `_dark` variants; the tree and the pinned list allow `AnimatedIcon` in their renderers), its title (bold when unread, grey without a process, grey italic when settled), its task count and, under `recent` only, its project; `SessionTrailer` paints the age on the right. Below it (`sessionNode`): the folder it works in (`workDir`), its added directories, each followed by a row of the branch checked out there (`BranchRow`, none outside a repository, detached or for a folder gone, since `Git.head` reads nothing for a missing folder rather than the repository above it), a folder gone in grey italics; the panel reads branches and missing folders off the EDT and rebuilds the tree when either changes, its brief as a group (goal, tasks), the agents it sent to the background as the group Agents (`AgentsGroup`, `AgentRow`: count and, while its process runs, how many have no end yet, bold; each with its description and `backgroundState`, its prompt in the tooltip, opening its output file; in `BACKGROUND_ORDER`, as Session Context lists them), the files it wrote other than outputs as the group Files, then its outputs (`OUTPUT_EXTENSIONS`). Status, settled, Desktop, the profile when not `default` and a project the row does not name go in the tooltip (`tooltipLines`). A group row (folder, project, `recent`, `sessions`) shows on its right the number of sessions it holds as shown and the dot of the most urgent in its session icon's colour (`folderSummary`, `Urgency`: needs input amber, unread blue, working an orange ring). A project row and a folder bound to a project have the project's icon, as Air and the Welcome screen (`RecentProjectIconHelper`: `.idea/icon.svg`, else initials on a colour picked from the path); other folders a folder icon. Their directories are followed by the branch checked out there in brackets (`Git.headBranch`, read from the HEAD file, not git, off the EDT on every refresh of the tree; none when detached). The pinned list (`PinnedRenderer`) lists sessions needing input first, then unread ones, then the rest, newest first within each (`pinnedSessions`), with the same icons in rows of two lines: icon, title and age, then by status (`secondLine`, `PinnedLines.kt`): needing input, the registry's `waitingFor` (a short reason such as `permission`, else "Needs input") on an amber row (`NEEDS_INPUT_TINT`); the renderer paints each row's background itself (`pinnedBackground`: hover, else that amber, else the list's), so a selected row shows no selection background; otherwise its project (`ClaudeSession.project`, in `projectColor`) · the branch of `workDir` · the brief's count, with a bar of the brief's progress while it works. `SessionTrailer` paints the age and the hover buttons in the first line (`PinnedLayout.firstLine`). The list is as high as its lower edge was dragged to, above or below its rows (`pinnedEdge`, application property `dev.myair.pinnedMaxHeight`, unscaled px), until dragged as its rows up to 40% of the panel, at least one row and leaving the tree 60 px (`pinnedHeight`), scrolling beyond, and hidden once loaded and empty. View Options sets the density of both (`Density`, application property `dev.myair.density`): Compact (26 px rows, 16 px icons) or Loose, as Air (34 px rows, 20 px icons, wider icon gap), the hover buttons Pin and Settle included; the font size grows rows further. The session of the window's active session tab (`ActiveSession`) has a bar at the left edge of its rows in the tree and the pinned list (`paintActiveBars`), with no background of its own; View Options' Select Session of Active Tab (application property `dev.myair.followActiveTab`, default on) selects its first row in the tree, expanding the rows above it (which the tree state then keeps), and scrolls the pinned list to it whenever the active tab's session changes, once the tree shows it when it does not yet. A double-click or Enter opens a row's session (a file row its file, a group row toggles); View Options' Open Sessions with Single Click (application property `dev.myair.singleClick`) makes a plain left click on a row of a session, or of one about it other than a file (`sessionOf`), open it too, in the tree and the pinned list, and a click on a tree row with children expand or collapse it (`clickTree`; the double-click then leaves such a row alone, since the first click toggled it); a click with a modifier only selects.
- `SessionContextPanel` fills its own tool window, Session Context (right, below Claude Sessions; `SessionContextToolWindowFactory`), in the font size set in the Claude Sessions View Options (`PaneFont`, shared by every window and applied to each component the pane builds), keeps itself readable when narrow (rows of chips, links and buttons are `WrapLine`s that wrap instead of being cut off, cards have no minimum width, the changes list shows the file name before its folder and the changes tree scrolls sideways when wider than its card: `horizontallyScrolled`), and describes, as white rounded cards (`ContextCard`, `ContextCards.kt`), the session of the active session tab (`ActiveSession`): first its title (a click selects and focuses that tab, back from a file opened from the pane), then model and effort chips with the age on their right (no status: the tab and the session lists show it) (`modelName`) and beside them a button that starts a session continuing this one (`continueSession`, `CONTINUE_SESSION_ICON`, a small asterisk with a blue arrow) and one that starts New Session Here as the tab's header does (`newSessionHere`): its model, effort and added directories, in the folder it works in (its worktree, no new one), its first message naming the session's id and transcript (`continuationPrompt`), then, kept while another file is selected and its tab stays open: project, with the folder the session runs in relative to it when it is another one (the work tree of `workDir` when the session moved to another one than it started in, `workTreeOf`; a `cd` within its own tree moves nothing), then that folder's branch, then "Started in <folder> on <branch>" naming what changed since the start (`Git.state` of `workDir`, read on one background thread only when that session or its live entry changed and the pane is showing; only the latest read lands; no `.git` up the path means no repository, any git failure is shown), worktree, Desktop, added directories, each with its checked-out branch when in a repository (`Git.branchOf`, read with the state); its brief, goal and tasks as the tree shows them; Files, the files it wrote outside the work tree (all of them until git has been read) as the tree lists them (`fileLabel`); Outputs, the `md`/`html` files it wrote, newest first (`contextOf`, `SessionContext.kt`); its artifacts, opened in the browser; its background tasks, the running ones first with their start time (or "ended with its process" when the session has none), then the ended ones, latest first, with status, a failed command's exit code and duration, plus an agent's model, an agent's or workflow's tokens, tool uses and agents done, a monitor's event count and last event time (`backgroundState`), each opening its output file, and under it on one line its command or prompt, a click showing it whole in a dialog to select and copy (`CommandDialog`), or a workflow's script file; its MCP servers, paged like Files, and its skills, grouped by the plugin of a `plugin:skill` name (`skillGroups`, those of none first), each group collapsed until opened (every section and group keeps the state it was last toggled to, in every window and across restarts: application property `dev.myair.context.sections`, `SectionStates.kt`), without the left indent of other sections, above them the skills pinned by hand, named in full (`skillSections`; application property `dev.myair.context.pinnedSkills`, one list for every session); a skill's row has buttons that pin it and that select the session's tab and type `/<name> ` into its prompt (`SessionPane.type`, unsent); a skill opens to the `description` of its frontmatter and its files as a tree (a command: its one file), read off the EDT by `skillFiles` (`SkillFiles.kt`) from where `claude` keeps them: `~/.claude/skills`, `<cwd>/.claude/skills`, `commands/` of both, an installed plugin's `installPath` (`plugins/installed_plugins.json`, skills possibly in subfolders), `plugins/synced/*/<plugin>~*`, `skills/synced/*` for `anthropic-skills`; a skill found nowhere is built into `claude`, one found twice throws; under the description its origin (`SkillOrigin.kt`, read from local files only, no network): for a plugin skill the plugin and marketplace, the installed version (a commit when the marketplace pins one) and the marketplace's as of its last refresh (`known_marketplaces.json` `lastUpdated`; the entry's `version`, else its source's `sha`, else the `plugin.json` in the marketplace's clone), told by `updateState`, and a GitHub link to the skill's folder at the installed `gitCommitSha` (in the marketplace's repository for a `./path` source, else in the source's own); for a skill the `skills` tool linked into `~/.claude/skills` from `~/.agents/skills`, its repository and folder from `~/.agents/.skill-lock.json`, with no update state; and its changes against its base (`Git.state`): the base stored for its branch, else the default branch, shown after the branch in Environment (`branch → base`, `ShrinkingLine`: the base gives way first) and changed there from a searchable popup of every other branch, nearest first: fewest commits of HEAD it lacks, then fewest of its own, so a base that moved on since the fork stays near the top (`Git.nearestBases`, `%(ahead-behind:HEAD)`) (a detached HEAD cannot store one; a stored base that names no commit, one with no history in common with HEAD, or a default branch that cannot be told leave the branch row and say why in Changes, never replaced by another base); the files changed since `git merge-base <base> HEAD` in the work tree, untracked ones counted as added (not nested repositories or worktrees), with `+added −removed`, each with its stage (`FileChange.Stage`: uncommitted when the work tree differs from HEAD or it is untracked, else committed when it changed in `<upstream>...HEAD`, the branch's upstream from `%(upstream)`, or always without an upstream or with one gone, else pushed), filtered by All / Not pushed / Uncommitted, each with its count, on one line with the list/tree toggle and a `...` menu of the reviews below (`ChangesFilter`, application property `dev.myair.context.changesFilter`; the reviews do not follow it; no line totals for the whole diff), an uncommitted file marked by an orange dot in the tree, as a list or, by a toggle kept for every pane (application property `dev.myair.context.changesAsTree`), as Branch Diff's tree: folders first, single-folder chains merged, each with its file count and `+added −removed` (`changeTree`, `ChangeTree.kt`), folders of tests (`test`, `tests`, `__tests__`, `openByDefault`) closed and the rest open until toggled by hand, which is kept until another session shows; a file opening the diff of all of them on it in the editor's preview tab, which the next file replaces until it is kept by a double-click or an edit (`showBaseDiff`, `BaseDiff.kt`: a `ChainDiffVirtualFile` opened with `usePreviewTab`, honoured only with Enable preview tab on, else a tab each; no external diff tool; contents from `git show`), the menu's Show Diff all of them in one editor tab, the IDE's combined diff (`showCombinedBaseDiff`, built as the internal `ShowCombinedDiffAction.showDiff` builds it), Show as Folder Tree a dialog of them as a folder tree (`showBaseChangesTree`, `VcsDiffUtil.showChangesDialog`), Review in Plannotator (shown only with `plannotator.exe` on PATH, looked up once) its browser review of them (`reviewInPlannotator`: `plannotator review --git --base <base> --diff-type since-base` in a Terminal tab at the work tree); all three take `Change`s (`changesOf`, built off the EDT in a read action: each looks its file up in the VFS), so plugin.xml depends on the content module `intellij.platform.vcs.impl` (`bundledModule` in Gradle), which a session's menu also offers (Show Changes vs Base). It follows `ActiveSession` (`service/ActiveSession.kt`, a project service: the selected session tab, else the last one while it stays open, `activeTab`; it notifies when the tab, its session, that session's head or live entry changes) and service changes; the counts change only with them, not with an edit alone.
- Branch Diff (the separate plugin `dev.kosmala.branch-diff-tree`, `E:/dev/projects/personal/idea-branch-diff`, a tool window of the files changed against a base) follows the active session when it is installed: `my-air-branch-diff.xml`, loaded by an optional `<depends>`, registers `SessionDiffTargetProvider` (`branchdiff/`) on its `diffTargetProvider` extension point, whose target is the work tree of `ActiveSession`'s session's `workDir` (a tab no scan has seen: its `cwd`; a folder gone or outside a repository throws, shown in Branch Diff) against `Git.baseOf` (the stored base, else the default branch, the one `Git.state` counts against), labelled with the session's title. Its `subscribe` is `ActiveSession.subscribe`; a base chosen in Branch Diff goes through `setBase` to `Git.setBase`, then `ActiveSession.baseChanged`, which Session Context's base popup calls too, so both panes re-read it (`baseGeneration` keys Session Context's git reads). Gradle compiles against Branch Diff's built zip (`localPlugin`), so run its `buildPlugin` first; the sandbox then loads it too. The dependency points this way because My Air's classes (Java 25, IU-263) are newer than Branch Diff's toolchain (Java 21).
