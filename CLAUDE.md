# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

IntelliJ plugin "My Air" (Kotlin), a small take on JetBrains Air: lists Claude Code sessions, resumes them in editor tabs, tracks their live status, and switches to wherever a session already runs, across windows and across IDE instances. Windows only in practice (Win32 calls through JNA).

## Commands

```bash
./gradlew test buildPlugin                                   # all tests + build/distributions/my-air-0.1.0.zip
./gradlew test --tests dev.myair.store.TabStoreTest          # one class
./gradlew test --tests 'dev.myair.store.TabStoreTest.a withdrawn*' # one test (names are backtick sentences)
```

Run the sandbox IDE without the `CLAUDE*` variables of the Claude Code session that launches it. Inherited `CLAUDE_CODE_CHILD_SESSION` makes every `claude` started in a sandbox tab turn transcript saving off, and `--no-daemon` keeps a running Gradle daemon from passing them on:

```bash
env $(env | grep -o '^CLAUDE[A-Z_]*' | sed 's/^/-u /') ./gradlew --no-daemon runIde
```

Sandbox log: `.intellijPlatform/sandbox/my-air/IU-2026.2.3/log_runIde/idea.log` (appended across runs). Restart the sandbox after `buildPlugin`; it does not pick up a new build by itself.

## Build setup

- Compiles against the locally installed IDE (`local("E:/dev/apps/jetbrains/IntelliJ IDEA Ultimate")`, IU-262.10968.63), not a downloaded one. Its classes are Java 25 (class version 69), hence `jvmToolchain(25)` with the IDE's own JBR registered in `gradle.properties`.
- Tests are plain JUnit 5 without the IntelliJ test framework. IDE jars are on the test classpath, so tests may use libraries the IDE ships (Gson, JNA), but not platform services. Keep logic that needs tests out of IDE-service code, as `retarget` (`TabRetargeting.kt`) and `TabStore` are.
- `ClaudeHomeWatcherTest` and `TabStoreTest` measure real file-system events and timings.
- `air-plugin/` is the unpacked JetBrains Air plugin (gitignored), kept as a reference only: inspect it with `javap`, never put it on the classpath.

## Where the data comes from

All state is read from files `claude` writes; the plugin never talks to a `claude` process.

- **Transcripts** `~/.claude/projects/<encoded-cwd>/<sessionId>.jsonl` (`ClaudeSessionScanner`). The directory name encodes the cwd lossily, so the cwd comes from the first line carrying a `cwd` field. Title: the last `custom-title` line, else the last `ai-title` line, else the first human prompt; a skill the human ran counts as `/name args` (a line opening with `<command-message>`), a built-in command such as `/model` does not. Date: the `timestamp` of the last `user`/`assistant` line or `system` `local_command` line, outside sidechains and `isMeta`; not the file's mtime, which a mere `--resume` bumps by appending `attachment`, `mode`, `last-prompt` and similar lines. Project: on every refresh a session whose cwd is in a linked worktree that `.git/worktrees/*/gitdir` of a directory sessions ran in lists gets that main checkout as `ClaudeSession.project` (`inProjects`), so the folder bound to the project holds it wherever the worktree lies; once git forgets a removed worktree, its sessions keep their own cwd. A session Claude Desktop runs gets the folder it was started in (`originCwd` of `%LOCALAPPDATA%/Claude-Data/*/claude-code-sessions/*/*/local_*.json`, keyed by `cliSessionId`, `DesktopSessionReader`), so a removed Desktop worktree keeps its sessions in the project too; such a session is marked "Desktop" in its row. Added directories: `additionalWorkingDirectories` of the last `attachment` line of type `environment` (`--add-dir`, Desktop's extra folders), shown under the session in the tree. Model and effort: `message.model` and the top-level `effort` of the last `assistant` line outside sidechains, skipping `claude`'s own error replies (model `<synthetic>`). Changed files: `Write`/`Edit`/`MultiEdit`/`NotebookEdit` `tool_use` items inside `"type":"assistant"` lines; `api-request-shape` lines also name those tools and must not count. Artifacts: the `toolUseResult` of an Artifact publish (`artifact_id`, `url`, `title`, `path`) outside sidechains, one per id, the latest publish naming it. Background tasks: a `Bash`/`PowerShell` result with `backgroundTaskId` (named by the call's `description`, else its command's first line), a `Monitor` result's `taskId`, an `Agent`/`Workflow` result with status `async_launched` (`agentId` and `description`, `taskId` and `summary`); its start is that result's `timestamp`, its output file the `Output is being written to:` path of a shell's result text or an agent's `outputFile`. One ends with a `queue-operation` `enqueue` line whose `<task-notification>` carries its `<task-id>`, a `<status>` (`completed`/`failed`/`killed`/`stopped`, any other throws; a monitor's events carry none), a `<summary>` naming a command's exit code and usually `<output-file>`; an agent sent another message notifies again, and the latest end counts. An agent's model is its launch result's `resolvedModel`; an agent's or workflow's `<usage>` (after its `<result>`, whose text may hold anything) gives tokens and tool uses, a workflow's also `agent_count`/`agents_done`/`agents_error`. A monitor's notifications without a status each count as an event (its final one may carry the last); an event opening with `[Monitor expired` ends it as expired. Tasks also die with their process, which the transcript does not record. Transcripts are append-only, so a rescan reads only complete lines after the stored offset; that state is saved in `~/.my-air/scan-cache.json` (by the first scan, then at most once a minute and on exit) for the plugin jar that wrote it (`pluginBuild`: path, size, mtime), so a restart of the same build reads only what was appended meanwhile, any other build everything; `subagents/` one level deeper is not listed.
- **Live registry** `~/.claude/sessions/<pid>.json` (`LiveSessionRegistry`), one per running `claude`: `sessionId`, `status` (`busy`/`shell`/`waiting`/`idle`; `shell` counts as working, as in claude's own list), `waitingFor`, `entrypoint`, `procStart`. A file outlives a killed process, so an entry counts only if the pid's start time equals `procStart`, a Windows FILETIME. `/clear` and `/resume` keep the pid and rewrite `sessionId`, which is how tabs follow their session. A file without `statusUpdatedAt` belongs to a `claude` still starting and is skipped.
- **Tab store** `~/.my-air/` (`TabStore`), owned by this plugin: `ides/<pid>.json` lists each IDE's session tabs, `requests/<pid>/` receives "focus this session" requests, `pins.json` holds the sessions pinned by hand, the running ones removed from the list and the settled ones (`Pins`; the list above the tree adds every session with a live process, `pinnedSessions`). Settled sessions are hidden from the list and the tree until the toolbar's Show All Sessions is on (`Pins.shown`); settling unpins, pinning unsettles. View Options can also hide from the tree (not the list) sessions whose last message is 3, 7, 14 or 30 days old. A removed running session returns once it has a newer message and no longer works; refresh prunes dismissals that are over. Writes go to a temp file and are moved into place.

Unknown registry statuses and missing fields throw rather than being skipped; a new `claude` release that changes these formats should fail loudly.

## How the pieces fit

Packages under `dev.myair`, by feature: `claude` (reading `claude`'s files: `ClaudeSession`, scanner, registry, watcher), `store` (files in `~/.my-air` and `writeAtomically`), `folders` (folder model, `structure.json` store and history, MCP change lists), `mcp` (the toolset and its queries and JSON), `service` (`ClaudeSessionsService`, the taskbar board, tab re-targeting), `editor` (session tabs and `ClaudeSessionOpener`), `tabs` (finding tabs and windows, cross-IDE sync), `actions` (menu actions, worktrees, `Git`), `toolwindow` (the Claude Sessions panel), `prompt` (the new-session panel of the empty editor area). Tests sit in the package of what they test. Classes named in `plugin.xml` and `my-air-mcp.xml` are found at runtime only, so a move must update them.

- `ClaudeHomeWatcher` watches `sessions/` and every `projects/<dir>/`, debounced 500 ms quiet / 700 ms cap (Air's timings). `ClaudeSessionsService` (application service) refreshes on its events plus every 60 s, holds the session list and live statuses for all projects, and after each change re-targets open tabs by pid (`retarget`) and notifies subscribed tool-window panels.
- `ClaudeSessionVirtualFile` + `ClaudeSessionEditor` host a terminal widget running `claude --resume <id>` (or `--session-id <new uuid>`, in a pinned tab) with `CLAUDE_CODE_NO_FLICKER=1` and `CLAUDE_CODE_IDE_SKIP_AUTO_INSTALL=true`. The tab learns the process pid from the tty connector; closing the tab ends the process. Tabs survive a restart: the file's URL is `myair-session://<id>?cwd=…&project=…` in `ClaudeSessionFileSystem` (`SessionTabUrl.kt`), computed from the session it shows now, so the platform saves it with the open tabs (order, splits, pins) and resolves it on startup, always as a new tab and never into Recent Files (`OptionallyIncluded`); a restored tab gets `--resume`, or `--session-id` when the session has no transcript yet, and starts when first selected, but not while its directory is gone or the registry shows its session running, where it says so and offers Switch to Window / Open Anyway. `CenteredTerminal` gives the terminal the number of columns set as Session tab width (`MyAirSettings.terminalColumns`, 0: the whole tab) and centers it; `CenteredTerminalTest` lays out a real JediTerm widget.
- `ClaudeSessionOpener.open` goes, in order: a tab in this IDE (`SessionHosts.findTab`, which includes Air's tabs read through reflection on `getThreadId`/`getSessionId`) → a tab in another IDE running this plugin (`TabsSync.focusElsewhere`: `AllowSetForegroundWindow` for that IDE, then a request file) → a warning when the registry shows the session running in another program, offering its window (`SessionHosts.hostWindow`, the nearest ancestor of the `claude` process that owns a visible window) → a new tab.
- `NewClaudeSessionInWorktreeAction` (toolbar and Tools menu, next to the plain new-session action) lists branches in a popup: the default branch (`origin/HEAD`; without `origin` the one local `main`/`master`), the 5 recent bases (application `PropertiesComponent`, keyed by the repository's main checkout), the rest. The pick becomes the base of branch `worktree-<name>` checked out by `git worktree add --no-track` in `<worktrees dir>/<name>`, the pick stored as the branch's base in the repository's config (`branch.<branch>.myAirBase`, `Git.setBase`, so `git branch -m` carries it), `<name>` being `worktreeName`: the pick without non-alphanumerics, today's date and the first 4 characters of the new session id (`main-2026-10-28-3fb8`); gitignored files matching `.worktreeinclude` are copied in, as `claude --worktree` does (`claude` itself takes no base branch). The worktrees dir is an application setting (`MyAirSettings`, the one class left in `dev.myair`, Settings › Tools › My Air), default `.claude/worktrees`, relative to the main checkout. `Git` (`Git.kt`) runs the `git` on PATH and throws with its stderr; the pure parts (`baseChoices`, `pushRecent`, `defaultBranch`, `worktreePath`) are in `Worktrees.kt`, and `GitTest` runs real `git` in a temp dir. The tree's menu on a project row, or on a folder bound to a project or lying in one, offers both new-session actions in that directory (`nodeDir`, `NewSessionInDirAction`), disabled when the directory is gone. Open in IDEA and Open in Terminal (`OpenInDir.kt`) sit beside them, on session rows too (`openDir`: the session's cwd) and as links under the project in the context pane's Environment section: IDEA focuses the open project of this IDE or opens it here, Terminal adds a tab at the directory to this project's Terminal tool window.
- Session configurations (`Preset`, `store/Presets.kt`) live in `~/.my-air/presets.json`, shared by every IDE and edited in Settings › Tools › My Air (`PresetsEditor`, `PresetDialog`; the fixed base is picked from the branches read off the EDT from the project field's repository, or the IDE project's when it is empty): name, `--model`, `--effort`, a project directory (none: the IDE project's), no worktree / a worktree off a fixed base / off a base picked in the popup (`startInWorktree`), `--add-dir` directories, and whether it gets its own toolbar button (an initials icon). `PresetsGroup` on the panel toolbar shows those buttons and a dropdown of all presets; it reads the file on every toolbar update, cached by modification time, and names a broken file in the dropdown. Model and effort apply only to new sessions: `--resume` gets no flags. A session's menu (tree and list) offers New Session with Same Settings and Save Settings as Configuration...; both take `presetOf(session)`: its model, effort, project, added directories, and a worktree with the base picked at start when its cwd is not its project.
- `PromptPanel` (`prompt/`), styled after Air's composer: a card with the first message, chips for the configuration (Default, then `presets.json`), model (default `opus`) and effort (default `medium`) and a send button; under it a bar with the workspace (current checkout or a new worktree) and the branch, the checked-out one or, for a worktree, the base picked in a searchable list (`baseChoices` of the configuration's directory's repository, read off the EDT, tagged current/default/recent by `branchTag`). A configuration sets the rest, each may then be changed, and the next panel opens on the last start's choices (`restore`, `PromptChoices.kt`; the base through the recent bases), or on a message typed and not sent with the choices and base it was typed with (`Draft`, `opening`; application properties `dev.myair.prompt.draft.*`, written on every change while there is a message, removed when it is sent or emptied). Ctrl+V of an image saves it as a PNG in `~/.my-air/images/` (images older than 30 days are deleted, off the EDT, whenever a panel opens: `pruneImages`) and of copied files keeps them where they are; either goes into the message as an `@path` mention, quoted when it has a space (`pastedMentions`, `PastedImages.kt`), which `claude` attaches at once, while a bare path it reads only with a tool call. The paste is an action on the text area, since the IDE's own paste takes only text. It starts the session through `startPreset`. The prompt goes last, after `--` (`Preset.claudeArgs(prompt)`): `--add-dir` is variadic and a lone word like `mcp` would be a subcommand. It fills the empty editor area (`PromptEmptyState`, platform EP `editorEmptyStateComponentProvider`, internal API in `fileEditor.impl`); every available `RICH` provider is stacked there, so Air's composer shows too unless its registry key `air.inline.empty.state.prompt` is off. `NewSessionWithPromptAction` (first on the main toolbar and the Claude Sessions toolbar, and in the Tools menu) shows the same panel in a popup.
- `taskbar/` is a separate WPF app (.NET 10, `Deskband11Lib.Wpf`) that hosts a window inside the Windows 11 taskbar: counts of sessions needing input, with an unread reply, and working; hover peeks at a flyout listing them in those groups, a click pins it. When a session comes to need input or gets an unread reply (`Board.Arrivals`, between two reads of the board, never on the first read nor without a live IDE), a bubble above the widget (`Bubble`) names it; it hides after 8 s unless hovered, drops a session that leaves that group, gives way to the flyout, and a click opens the session as a flyout row does. The bubble activates itself before asking the IDE: a click alone does not make a non-activated window the foreground, and without it the IDE cannot come forward. Every IDE writes `~/.my-air/taskbar/board.json` when a refresh changes it (`boardSessions`/`boardJson` in `TaskbarBoard.kt`, written by `BoardWriter`); the app reads it and `ides/*.json`, and a click on a row sends a focus request to the IDE with the session's tab, else any IDE, whose `TabsSync` then opens the session. Unread: an idle session whose last message is newer than `~/.my-air/seen/<id>` (epoch ms, one file per session, `Seen.kt`); the IDE marks a session seen when its tab is selected in the active window (`SessionHosts.visibleSessions`, on tab selection, IDE activation and refresh), the app when a row is clicked, and a session met for the first time is marked at its last message. The same unread sessions (`ClaudeSessionsService.unread`) get "unread reply" and the idle icon with a blue dot in the rows and on their tab. `TaskbarBoardTest` and `taskbar/tests/BoardTest.cs` parse the same JSON literal. Build/test: `pwsh taskbar/build.ps1` runs `dotnet test taskbar/tests`, stops a running `MyAirTaskbar` (it locks its exe), runs `dotnet build -c Release taskbar` and starts the new build.
- `SessionContextPanel` sits between the list and the tree (View Options › Show Session Context hides it) and describes the session of the selected session tab, kept while another file is selected and its tab stays open: project, branch (`Git.state`, read on one background thread only when that session or its live entry changed and the pane is showing; only the latest read lands; no `.git` up the path means no repository, any git failure is shown), worktree, Desktop, added directories; its brief, goal and tasks as the tree shows them; Files, every file it wrote as the tree lists them (`fileLabel`); Outputs, the `md`/`html` files it wrote, newest first (`contextOf`, `SessionContext.kt`); its artifacts, opened in the browser; its background tasks, the running ones first with their start time (or "ended with its process" when the session has none), then the ended ones, latest first, with status, a failed command's exit code and duration, plus an agent's model, an agent's or workflow's tokens, tool uses and agents done, a monitor's event count and last event time (`backgroundState`), each opening its output file; and its changes against its base (`Git.state`): the base stored for its branch, else the default branch, shown after the branch in Environment and changed there from the same branch popup (a detached HEAD cannot store one; a stored base that names no commit, one with no history in common with HEAD, or a default branch that cannot be told leave the branch row and say why in Changes, never replaced by another base); the files changed since `git merge-base <base> HEAD` in the work tree, untracked ones counted as added (not nested repositories or worktrees), with `+added −removed`, opened in the platform diff window (`showBaseDiff`, `BaseDiff.kt`, contents from `git show`), which a session's menu also offers (Show Changes vs Base). It follows tab selection and service changes; the counts change only with them, not with an edit alone.
- `TabsSync` republishes this IDE's tabs on tab open/close (project listener), project startup and re-targeting; it withdraws its file on dispose.

Code, comments and strings are in English.
